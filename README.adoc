= ElkRb, in Rust

image:https://img.shields.io/badge/license-BSD--2--Clause-blue.svg[License]

== Purpose

elkr is a Rust implementation of the Eclipse Layout Kernel (ELK) layout
algorithms, ported from the pure-Ruby https://github.com/metanorma/elkrb[ElkRb].
It computes positions and routes for node-link diagrams: the same ELK JSON
interchange that elkjs and elkrb speak goes in, and a laid-out graph with
node coordinates and edge sections comes out.

The crate exists because layout is part of the reproducibility contract of
https://github.com/etassia[Etassia's] rendering pipeline: the position of
every node belongs to the byte-identity guarantee as much as the stroke of
every edge. Layout here is therefore deterministic — the same input graph
and options always produce the same coordinates — and versioned, so a
layout change is a visible, pinned change.

== Status

`elkr 0.1.1` carries all fifteen of the fifteen algorithms ElkRb implements:

[cols="1,2,1"]
|===
|Algorithm |Description |Status

|Layered (Sugiyama)
|hierarchical diagrams with directed flow
|v0.1 — cycle breaking (DFS), longest-path layering, barycenter crossing reduction, sequential coordinates, straight edge sections; directions RIGHT, LEFT, DOWN, UP

|Force
|organic, symmetric layouts using force simulation
|v0.1 — Fruchterman-Reingold-style repulsion plus spring attraction with linear cooling; the initial scatter comes from a fixed-seed SplitMix64 stream, so the layout stays byte-identical where elkrb's `Kernel#rand` scatter cannot; options `iterations`, `repulsion`, `temperature` (with `elk.force.*` aliases); preset node positions are preserved as the simulation start; edges route straight, center to center

|Box
|simple grid-based arrangement
|v0.1 — uniform grid, rows first, cells sized by the largest node; `aspect_ratio` (1.6) sets the column count

|Fixed
|preserve existing positions
|v0.1 — absent coordinates become the origin and the result shifts onto the padding

|Random
|random node placement (seeded, so still deterministic)
|v0.1 — the padded-area bounds from elkrb with `aspect_ratio` (1.6); the scatter draws from the shared fixed-seed SplitMix64 stream

|Stress
|quality-focused layout with stress minimization
|v0.1 — stress majorization over the hop-count matrix (Floyd-Warshall, edges 1.0), circular start, epsilon 0.0001 convergence, iterations 500; unconnected pairs pull on nothing

|MRTree
|multi-rooted tree layout
|v0.1 — trees from the nodes no edge points at, leaves at their slots, parents centered over children, levels 80 apart; a placed node is never re-added, so cycles terminate (elkrb recurses forever)

|Radial
|circular and radial node arrangement
|v0.1 — even angles on one circle; the radius fits the circumference on the average node size (times 1.2 of slack, never under 100); nodes centered on their points

|RectPacking
|efficient rectangle packing
|v0.1 — shelf packing, tallest first, the 80 percent uniformity rule; faithful to elkrb, where the tallest-first order keeps the whole graph on one shelf

|TopdownPacking
|grid-based treemap layout
|v0.1 — cols = ceil(sqrt(n)), uniform cells from topdownpacking.nodeWidth or the average dimensions shaped by topdownpacking.aspectRatio (1.0); every node takes the cell size

|Libavoid
|"A*" pathfinding connector routing
|v0.1 — orthogonal A* over the nodes inflated by libavoid.routingPadding (10), segment and bend penalties, visibility simplification; faithful to elkrb, whose paths start inside their own obstacle and so fall back to the direct route

|Edge routing and labels
|orthogonal bends and edge label placement
|v0.1 — per-edge `edge.routing: orthogonal` (elkrb's midpoint bends), and the label pass: each edge label centers on the route's arc-length midpoint and stacks above the line, elkrb CENTER semantics

|Ports
|fixed connection points on node boundaries
|v0.1 — side detection, index ordering, even distribution, and port-anchored edge sections (layered and straight routing); elkrb PortConstraintProcessor semantics

|VertiFlex
|vertical flexible column layout
|v0.1 — round-robin columns (vertiflex.columnCount 3, balanceColumns on), column widths flexing to the widest node; vertiflex.columnSpacing 50, vertiflex.verticalSpacing 30 overridden by elk.spacing.nodeNode. One deliberate deviation: balanceColumns parses as a boolean, where elkrb reads the Ruby string in which "false" is truthy

|DISCO
|disconnected component layout
|v0.1 — BFS components, each laid independently by disco.componentAlgorithm (layered), arranged row, column or grid with disco.componentSpacing 20; edges re-route on the final positions

|SPOrE Overlap
|overlap removal optimization
|v0.1 — overlapping pairs (inflated by half of spore.nodeSpacing 10) push apart along the dominant axis until clean or spore.maxIterations 50; the knobs parse as numbers, where elkrb reads raw strings

|SPOrE Compaction
|whitespace compaction
|v0.1 — sweeps along spore.compactionDirection (both), each node pulled to the boundary its overlapping predecessors allow plus spore.nodeSpacing 10; unblocked nodes ride to the origin, faithful to elkrb
|===

Also on the roadmap, in pipeline order: hierarchical (nested) graphs.
Ports, orthogonal edge routing, edge label placement, and the DIM
adapter shipped in 0.1.2.

== Usage

The library:

[source,rust]
----
let mut graph: elkr::ElkGraph = serde_json::from_str(&input)?;
elkr::apply(&mut graph)?;              // honors elk.algorithm (default: layered)
println!("{}", serde_json::to_string(&graph)?);
----

The command line:

----
elkr layout graph.json -o laid-out.json
elkr dim document.json -o laid-out.json     # a DIM 0.1 document
----

The DIM adapter takes a Diagram Interchange Model 0.1 document, lays
out its embedded graph with the document's own layoutOptions, and
merges the positions and edge sections back in — every field the
engine does not speak (content blocks, style, notation) rides through
untouched.

Spacing follows the ELK options `elk.spacing.nodeNode` (default 20) and
`elk.layered.spacing.nodeNodeBetweenLayers` (default 60); direction follows
`elk.direction` (`RIGHT` by default). Unknown edge endpoints are errors;
self loops are ignored by the layered layout.

== Verification

`cargo test` carries the semantic tests: longest-path layering on a
diamond, spacing knobs, direction transpose and mirror, cycle reversal
(sections keep the authored direction), an elks-style JSON round trip, and
the force simulation's invariants — the scatter bounds, preset-position
preservation, connected nodes converging closer than unconnected ones,
center-to-center routing, and byte-identical determinism. The determinism
test asserts byte-identical output for repeated layouts of the same input.

== Relationship to ElkRb

elkrb is the pure-Ruby implementation this crate ports. The algorithms,
option names, and the ELK JSON interchange match elkrb's semantics, and the
two are expected to stay behaviorally aligned: a graph laid out by elkrb
and by elkr under the same options converges as the ports mature, with the
convergence proven by shared fixtures.
